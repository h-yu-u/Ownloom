## Coding 多轮缓存实测

2026-10-29，在 `c2fa21e4ce4e02c192322c60a0f0246a54830aaf` 加本轮工作区修改上，沿用前节 Mac M5 Pro / 64 GiB、Node 22.23.1、Python 3.12.13、MLX 0.32.1、MLX-VLM 0.6.14、Pi 1.2.0 及同一 Qwen3.8-27B-Uncensored 4bit 主模型、MTP/DFlash2。使用合成项目资料与独立进程/临时资料库，模型只读加载；没有执行个人项目中的命令。实现边界见 [Coding 多轮前缀缓存](./subsystems/runtime.md#coding-多轮前缀缓存)。

引擎对照先用 11,302 token 合成项目历史建立缓存，再提交相同“帮我启动服务”输入（11,326 token、温度 0、最多 128 输出 token）。每种模式分别测一次暖缓存追问、一次重复追问及一次无缓存请求；下表使用第一次追问，耗时从调用引擎到完整工具调用返回，不包含模型加载或命令实际启动。

| 方案     | 无缓存   | 缓存命中 | 等待减少 |
| -------- | -------- | -------- | -------- |
| DFlash2  | 26.61 秒 | 1.33 秒  | 95.00%   |
| MTP      | 26.03 秒 | 1.50 秒  | 94.25%   |
| 关闭草稿 | 26.76 秒 | 2.22 秒  | 91.72%   |

三种模式首次追问均复用 11,286 token，并将检查点推进到 11,310；重复追问命中推进后的检查点。每种模式的冷热工具名称和参数均一致，为 `run_command` / `npm run serve`，不比较随机调用 ID。DFlash2 含特征快照约 0.94 GiB，其他两种约 0.85 GiB。此处是单个固定任务的响应等待改善，不是生成 token/s 提升、统计分布测试或所有代码任务的速度保证。

完整产品链路通过临时项目 `HISTORY.txt` 引入历史，首个 Pi 运行读取后完成，随后在同一会话提交新运行“帮我启动服务，我要看下效果”。DFlash2 实际输入 14,315 token，复用 14,275，仅重新处理 40；Runtime 推理约 1.302 秒，提交到命令审批约 1.455 秒。Pi usage 确实记录 `input=40`、`cacheRead=14275`，总上下文仍包含缓存部分。测试在审批阶段取消，未执行启动命令；运行终态 `cancelled`，Supervisor 退出码 0。该证据覆盖跨运行、工具结果和 Provider usage，不代表真实服务器启动耗时。先前直接发送超长合成用户消息的探针被产品长度校验拒绝，没有计入成功样本。

`pnpm check` 与 `pnpm test` 通过，使用前节 Python 3.12 环境。完整测试含前端 392 项、Runtime 396 项、Coding 110 项，另有 Runtime 策略 5 项、验收工具 8 项、命令入口 10 项。初次 `pnpm test` 的 7 项 HTTP 集成用例被受限环境禁止绑定回环端口，之后在允许回环监听的隔离环境重跑通过。最后将模型范围限制在已验证的 `qwen3_5` 配置，并补充退出缓存回归，定向 19 项与全量静态检查通过。缓存单元回归覆盖长前缀、检查点推进、历史修改/缩短、会话与语义隔离、取消/失败释放、包含草稿特征的容量上限、未知尺寸和存取失败；特征回归验证滑动窗口数值与绝对位置恢复。能力授权回归验证新运行继承同会话范围且请求不能冒用范围，普通聊天/压缩与不支持模型继续退出缓存。
