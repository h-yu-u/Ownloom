# Ownloom 文档

[English overview](../README.md) · [中文介绍](../README.zh-CN.md)

本目录按读者和变更原因组织。用户操作、长期规范、当前实现与验证证据各有维护位置；同一事实只在所属文档详述，其他入口链接它。

## 从哪里开始

| 你要做什么                     | 阅读入口                                                                              |
| ------------------------------ | ------------------------------------------------------------------------------------- |
| 使用工作区、配置模型和管理数据 | [用户手册](reference.md)                                                              |
| 从源码启动、运行检查或生成契约 | [开发指南](development.md)                                                            |
| 理解进程、依赖和状态所有权     | [系统架构](architecture.md)                                                           |
| 修改或审查代码                 | [编码规范](code-standards.md)、[贡献指南](contributors.md)、[经验记录](../LESSONS.md) |
| 找到某项行为的源码和维护边界   | [子系统索引](subsystems/README.md)                                                    |
| 判断验证覆盖及发布准备情况     | [验证矩阵](verification.md)、[发布验收](release-acceptance.md)                        |
| 自动构建并发布正式版           | [版本发布](release.md)                                                                |

## 文档职责

| 层次           | 所属文件                                           | 更新触发条件                                                 |
| -------------- | -------------------------------------------------- | ------------------------------------------------------------ |
| 产品入口       | 根目录两份 README                                  | 定位、支持范围、快速开始、许可或入口变化时同步更新英中版本。 |
| Agent 入口     | 根目录 AGENTS.md                                   | 阅读顺序、任务边界、必要检查变化；不保存动态验收结果。       |
| 长期系统规范   | architecture.md、code-standards.md                 | 系统约束或工程政策被明确修改；说明理由、影响和验证。         |
| 产品维护参考   | subsystems/\*.md                                   | 职责、接口、状态、执行路径、失败行为或兼容约束变化。         |
| 使用与开发程序 | reference.md、development.md、contributors.md      | 用户步骤、实际命令或贡献流程变化。                           |
| 验证与发布     | verification.md、release.md、release-acceptance.md | 新增可审计证据、限制被验证解决，或发布步骤变化。             |
| 经验与设计理由 | LESSONS.md、对应 issue/PR                          | 有证据的复盘，或明确采纳/取代一项重要设计决策。              |

长期规范不跟随每日功能状态重写；确需改变时，必须连同约束所保护的调用链一起评审。子系统参考描述当前行为，计划、实验结论和待实施方案放在对应 issue/PR；已经失效的阶段清单由 Git 历史保留。

## 事实来源

| 事实                     | 权威来源                                                                                                                                             |
| ------------------------ | ---------------------------------------------------------------------------------------------------------------------------------------------------- |
| 工作区命令与版本         | [package.json](../package.json)、[.nvmrc](../.nvmrc)及各项目锁文件                                                                                   |
| HTTP 契约                | [HTTP 入口与 DTO](../services/runtime/src/mlx_studio_runtime/entrypoints/http/)，生成到 [API 类型](../packages/api-client/src/generated-schema.d.ts) |

| 应用名称、标识与打包配置 | [tauri.conf.json](../apps/desktop/src-tauri/tauri.conf.json)                                                                                         |
| 现有自动化门禁           | [CI](../.github/workflows/ci.yml)、[检查脚本](../scripts/)与相关测试                                                                                 |
| 具体行为与限制           | 所属子系统的源码链接；冲突时先核对代码和测试，修正文档                                                                                               |
| 发布结论                 | 指定提交、制品摘要、环境和原始验收报告；测试名或历史文字不代替结果                                                                                   |

## 维护约定

按[子系统文档维护规则](subsystems/README.md)在同一 PR 更新所属说明。使用可点击的相对源码链接及符号名，不引用易漂移的行号。私有 `.build/` 输出不能作为公共链接；需要验收证据时附经过脱敏的 PR/Release 附件并注明范围。

提交前运行 `pnpm check docs`，检查必需入口、本地链接、标题锚点和格式；再人工核对事实与双语承诺。外部站点可用性、模型兼容性和运行结果仍需对应验证。
