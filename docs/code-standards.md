# 编码与评审规范

[文档入口](README.md) · [系统架构](architecture.md) · [子系统参考](subsystems/README.md) · [贡献指南](contributors.md)

本文件维护长期工程约束。实现细节归属子系统，操作命令归属[开发指南](development.md)，实际检查结果归属提交/PR 和[验证矩阵](verification.md)。不能把目标、人工评审项或一次验收描述为已经存在的自动门禁。

## 变更范围与完整性

- 每项变更服务于明确目标。无关重构、依赖升级、额外功能和政策变化分别处理。
- 从用户输入追踪到结果与持久化，检查所有调用者、错误分支和同类场景。修改公式、默认值、状态或协议时，重新核对依赖它们的界面、缓存、生成文件、测试和文档。
- 读取、解析、校验或 hash 失败表示未知，不能当作空、无变化或成功。权限及完整性检查失败时拒绝执行；有已读取的有效数据时保留它并明确标记过期。
- 用户显式配置优先于默认值。改变默认值、存储格式或兼容行为时，写明受影响用户、迁移与恢复方式。
- 优先纯函数、不可变转换和组合；副作用必须具有明确所有者与清理路径。仅为真实变化点引入抽象，不创建无明确主题的万能 `utils`、`helpers` 或 `common`。

## 分层与类型

遵守[架构中的依赖与状态所有权](architecture.md)。领域层不引入 Vue、Pinia、Naive UI、FastAPI、Pydantic、Tauri、SQLite 或 MLX。UI 组件不直接请求 HTTP；模型适配器不访问 UI 或会话仓库；Rust 不承载聊天和模型业务。

状态转换、能力推导、请求构造、校验、错误映射与调度判断优先纯函数。I/O 留在显式 API 客户端、Repository、文件/下载服务、Worker Host、Engine Adapter 和平台边界。Pinia getter、Vue computed 和领域函数不得执行 I/O。

| 层面             | 约束                                                                                                                   |
| ---------------- | ---------------------------------------------------------------------------------------------------------------------- |
| Vue / TypeScript | 使用 Composition API、`<script setup lang="ts">` 和严格类型；外部值从 `unknown` 校验，不用 `any` 或断言掩盖错误。      |
| 组件             | 页面组合、容器编排、展示组件 Props/Events；复杂规则放普通 TypeScript，生命周期副作用放拥有它的 controller/composable。 |
| 基础控件         | 复用 Naive UI；通用响应式能力优先 VueUse。自定义组件表达产品行为，不重复实现基础控件。                                 |
| Store            | 绑定组合根配置的 controller；不直接持有 RuntimeClient、SSE、计时器或 Object URL，不产生 Store 循环依赖。               |
| Python           | 使用 Python 3.12、Ruff、Pyright；公开接口完整类型标注。领域值优先不可变 dataclass，Pydantic 只用于入口 DTO。           |
| Runtime          | MLX 导入限于引擎适配器与 Worker 运行路径；不以隐藏单例持有模型，不阻塞 Supervisor 事件循环。                           |
| 异常             | 转换为稳定错误码；仅在进程或任务边界捕获宽泛异常，不吞掉内部错误。避免可变默认参数和隐式修改输入。                     |
| Rust / Tauri     | 维持原生交互和固定子进程生命周期边界，校验 command 参数；不接受任意可执行路径或通用 shell 命令。                       |
| 协议             | HTTP 和内部 RPC 各自从权威描述生成；不手写重复 DTO，不手改生成文件，协议不兼容时明确拒绝调用。                         |

## 状态与资源

异步界面区分初次加载、空结果、成功、失败、取消与必要的部分可用状态。读取失败不能显示成成功空列表；取消不应无限停在 `cancelling`。

每个异步资源都要回答：谁创建、谁释放、如何处理晚到结果、如何恢复。页面释放观察者和用户取消任务是不同操作。进程、定时器、流连接、Object URL、临时文件和事件订阅都必须显式清理。

模型能力来自 Manifest 和适配器契约，不按目录名或型号字符串猜测。未知、部分支持、不兼容和资源损坏要能区分。推理、持久化和文件发布的先后约束见对应子系统，不用 UI 状态代替后端终态。

## 安全与隐私

- `trust_remote_code` 默认关闭，扫描模型不执行模型仓库代码。路径、类型、大小、schema、权限和连接代际在所属边界校验。
- Runtime 使用 loopback 和独立认证边界；会话 Token 不持久化。秘密不能进入默认日志、公开 DTO、模型提示或诊断导出。
- 默认日志不包含完整提示词、回复、文件正文、媒体或凭据；错误保留必要 request/job 标识和稳定错误码。
- Markdown 默认不执行原始 HTML。用户可控外链通过平台 URL 校验，不能放开通用 Shell 权限。
- 不提交模型、用户数据、私有诊断、签名身份或凭据。新增网络访问或工具能力须说明数据流和授权范围。
- 备份、删除、恢复与预览具有不同语义；预览不提交写入，破坏性操作重新核对对象、引用和用户授权。

## 长度与复杂度

| 项目          | 软上限 | 硬上限 |
| ------------- | ------ | ------ |
| Vue SFC       | 220 行 | 320 行 |
| TypeScript    | 220 行 | 350 行 |
| Python / Rust | 250 行 | 400 行 |
| 函数          | 35 行  | 60 行  |

嵌套不超过 3 层；超过 4 个参数优先使用有类型的参数对象。超过硬上限需要书面解释，并明确保护的职责边界。生成文件、迁移与兼容性数据的豁免须在检查器中显式声明。

当前外层装配范围的函数长度例外：Runtime 的 `RuntimeApplication.__init__`、`create_app`、`register_conversation_routes`、`register_attachment_routes`，前端的 `createChatController`、`createChatDraftController`、`createChatStream`、`createChatAttempts`、`createAttachmentPreviewController`。其独立 handler/action 仍需保持小职责；不得把解析、检索或数据库规则塞进这些装配函数。

扩展模块的局部例外保留原有资源连续性理由：`guardedTransport`、`mcpResources`、`openPi` 同时维持 SDK 回调、连接代际、准入与 awaitable close；`ResourceResolver.resolve`、`Extensions.dispatch` 负责单一快照推导或协议分派；`AgentChat.execute` 连续处理审批、Pi 订阅与 finally 清理；扩展 controller 工厂、`McpServerForm.save` 和 composition root 保留局部响应式状态及装配。具体实现入口见[扩展参考](subsystems/extensions.md)。这些例外不豁免类型、依赖边界、文件硬上限与行为回归，新增职责仍须拆分。

[源码检查器](../scripts/checks/check-source-quality.mjs)执行文件硬上限和公共样式归属；函数长度、嵌套复杂度和例外合理性仍由评审负责。

## 测试与证据

选择覆盖实际风险的验证。纯函数用单元测试，Engine 用契约测试，API/SQLite 用集成测试，Vue 状态与交互用 Vitest/Vue Test Utils。原生 UI、打包应用和真实模型分别验证，不能相互代替。

- 行为修复应有在修复前失败、修复后通过的回归测试；记录失败原因。文档措辞、链接或纯格式变更使用对应静态检查，不编造运行时测试。
- 断言可观察的契约，覆盖边界值、失败、取消、重试、晚到事件和兼容输入；避免仅重复实现细节。
- 自动测试使用临时数据、模拟外部网络、受控进程和明确超时，不使用真实个人配置或凭据。测试开启的任务在结束前关闭或等待完成。
- 不比较完整的不确定模型输出。文本验证协议、内容非空、终态与取消后无增量；媒体验证格式、可解码、尺寸/帧数和元数据。主观质量单独记录。
- 基线测试失败也要明确报告并查明范围；不能把未通过或未运行写成通过。超出当前任务的缺陷记录为阻塞或明确后续事项，不隐藏它。
- 涉及网络或上游协议时，使用真实结构的 fixtures 和固定版本。实际服务验证要写环境与范围，不能用一个 mock 证明线上兼容。

Domain 90%、状态机/调度分支 100%、Application 与 Store/composable 80%、整体 75% 是人工维护的覆盖目标，当前不是覆盖率自动门禁，也不代表已经达成。

## 完成与评审

运行适用的 `pnpm check`、`pnpm test`、生成一致性、构建和平台检查，命令详见[开发指南](development.md)。文档检查只验证受支持的链接/锚点与格式，不验证语义、外部网页或模型能力。

说明变更目的、行为影响、验证命令与结果、未执行项、依赖变化和迁移要求。提交说明与 PR 保留足够的验证记录，不能只在临时对话里声称通过。评审对照实际 head；head 改变后重新检查相关结果，合并遵循维护者授权，不自动创建标签或发布制品。

使用 pnpm、uv 与锁文件；新增依赖说明用途、替代方案和影响，不顺手升级无关依赖。遵循维护者对 commit、push、merge 和 rebase 的授权。提交前检查差异中只包含当前任务所有的文件。
