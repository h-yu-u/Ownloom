# ADR 0001：显式边界、单活推理租约与数据所有权

[文档入口](../README.md) · [系统架构](../architecture.md) · [子系统维护](../subsystems/README.md)

- 状态：Accepted
- 范围：桌面、Runtime、推理 Worker、Coding Host 与持久化
- 决策记录目的：解释长期边界的理由与代价；当前实现和验证结果由子系统文档及[验证范围](../verification.md)维护。

## 上下文

Ownloom 同时包含响应式界面、原生桌面生命周期、模型加载、异步推理、文件工具、审批、数据库和媒体存储。如果把这些状态放进一个全能服务或前端 Store，取消、重连、崩溃恢复和模型切换将无法建立明确的资源归属。

模型推理与文件/网络工具的资源需求不同；一次 Coding 或 Agent 运行又可能包含多次模型调用。普通聊天、工具产品记录与最终模型上下文也有不同的事务和恢复需求。系统需要在复用模型资源的同时，保留各自的状态与协议边界。

## 决策

### 1. 使用显式组合根与窄端口

桌面、Runtime 和 Coding Host 各自装配具体依赖。Application 依赖明确用例端口，Domain 保存纯规则与值对象，适配器承担 I/O。不引入运行时依赖注入框架、万能 Context 或隐式插件发现。

前端 Pinia 入口暴露装配后的控制器；共享模型目录、Runtime 查询、任务观察与媒体缓存具有独立所有者。展示组件通过 Props/Events 交互，避免直接依赖平台和协议客户端。

### 2. 由 Supervisor 分配单活推理租约

ModelRuntime 持有 Worker 与驻留模型，JobScheduler 持有执行锁、排队、取消和资源失效门禁，JobLifecycle 管理持久化状态转移。Rust 管理固定 Supervisor 生命周期，不承载业务。

Coding/Agent 父运行不占长期推理租约。每次模型调用独立取得并释放租约，文件、网络、审批和媒体子任务通过各自边界协调。停止资源失败时拒绝新接纳，不能以清空 UI 状态代替释放成功。

### 3. 明确数据唯一所有者

Python 写普通聊天、模型目录、推理 Job 和媒体记录；Node 写 Coding、Agent 与扩展元数据；Pi transcript 是模型上下文的权威来源。跨进程查询与任务中心使用接口投影，不跨所有者直接读写数据库。

接纳消息与任务、保存结果与终态使用用例事务。先提交数据库，再发布对应事件。数据库以外的文件使用暂存、补偿、描述符和恢复验证，不宣称与 SQLite 构成分布式事务。

### 4. 把身份、版本和生命周期写入契约

提交编号绑定请求意图；相同编号不同意图返回冲突。连接 epoch、Worker 实例与尝试、扩展快照和文件摘要隔离晚到结果。模型登记 ID 不等于权重内容哈希，路径导入不等于托管删除权。

HTTP/OpenAPI、Host RPC 与 Worker 协议各有权威来源和版本，生成文件不手改。stdout 专用于协议，错误与诊断分流。

### 5. 恢复事实，不重放不确定副作用

页面退出只释放观察资源。显式取消必须收敛到终态，迟到成功不能覆盖取消。进程重启中断未完成任务、作废旧审批和运行凭据，保留可审查记录；不能自动重跑可能已经执行过的工具。

备份由各数据所有者导出，恢复导入独立 profile，校验所有内容并完成全部所有者导入后再切换指针，保留旧数据供回滚。

## 替代方案比较

| 方案                                    | 未采纳原因                                           |
| --------------------------------------- | ---------------------------------------------------- |
| 在 UI 或 Rust 中直接调用模型和持久化    | 混合交互、平台与推理生命周期，增加协议与恢复耦合     |
| 每个工作区启动独立模型服务              | 重复常驻大型模型，不能统一内存、取消与资源门禁       |
| 全能 Runtime Facade 暴露所有服务        | 依赖边界不清，用例可以绕过资源和事务所有者           |
| Python 和 Node 共享读写同一产品数据库   | 迁移、事务和崩溃恢复责任不明确                       |
| 自动扫描项目可执行扩展和全局 Agent 配置 | 项目内容可隐式改变行为、依赖和权限，无法冻结运行证据 |
| 重启后自动重放任务或工具                | 无法证明磁盘和外部副作用尚未发生，可能重复写入或执行 |

## 代价与后果

多进程与多协议增加契约生成、握手、诊断和恢复测试工作；单活推理会带来排队与模型切换成本。显式端口和投影需要额外装配，但能够让业务规则独立测试，并把故障收敛到明确边界。

多个数据所有者使一致备份需要屏障与分别导出；跨数据库、文件、transcript 的操作只能通过校验、补偿和幂等恢复协调。系统不会因此获得跨磁盘 exactly once 或操作系统级命令沙箱。

## 约束落实与后续变更

依赖方向、部分文件长度和生成漂移由仓库检查器约束；生命周期、取消竞争、恢复和权限依赖行为回归。相关入口见[代码规范](../code-standards.md)、[Runtime](../subsystems/runtime.md)、[Coding](../subsystems/coding.md)、[扩展](../subsystems/extensions.md)与[存储](../subsystems/storage.md)。

如果要引入并行模型、多所有者事务、远程 Provider 或自动执行扩展，应新增 ADR 说明被替代的决策、迁移和验证，不把新的能力写进本文充当既有事实。真实模型、最终包、正式签名和干净机器仍按各自验收层次记录。
